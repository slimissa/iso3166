## Known limitations at v1.0.0

Recorded in docs/PROVENANCE.md:

- `official_name` populated for a small set of entries; full
  population targeted for v1.1.0.
- `currency_codes`, `calling_codes`, `tlds` are `null` for every
  entry; targeted for v1.2.0.
- `languages` and `borders` are `null`; targeted for v1.3.0.
- The ISO 4217 snapshot (`tools/iso4217_snapshot.json`) does not
  exist; the cross-registry check is advisory.
- The withdrawn set is the representative 15 entries from Phase 1,
  not the full ISO 3166-3 record; the full set is v1.1.0.

## Cross-registry wiring

The ISO 3166 side of the cross-registry snapshot infrastructure is in
place as of v1.0.0:

- `tools/iso4217_snapshot.json` — placeholder, to be populated.
- `tools/check_iso4217_snapshot.py` — verifies the snapshot against a
  freshly published `iso4217.json`; advisory in v1.0.0.

The ISO 4217 side (the mirror) is tracked as a separate task on the
ISO 4217 repository.
