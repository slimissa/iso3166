## What this release proves

v1.12.1 closes the last three gaps from v1.12.0:
1. The four club arrays are now in the flat exports (CSV, Parquet,
   SQL), serialized as strings.
2. `eea_membership` now counts provisional application dates, so
   is_eea_member_at("BG", "2010-01-01") returns True (provisional
   from 2007-08-01 to 2011-11-09) instead of False (formal only).
3. The README field table lists all 24 fields.

The provisional-date design was Claude's, not the prompt's. The
prompt said "check both `data` and `meta.provisional_application`
in every wrapper." Claude rejected that (it duplicates data across
two places) and instead unions the provisional range into
`eea_membership` in the enrich tool. The array answers "when did
EEA rules apply?", which is the consumer's question. The snapshot
keeps the formal dates for provenance. The design is better.

The packaged CLI's `--csv` output is now byte-identical to
`iso3166.csv`. This gap existed since v1.11.0 (the packaged CLI's
column list lacked `introduced`); v1.12.1 fixes it.

## The capability phase is complete

The registry has the full temporal identity layer:
- introduced (when the code was born)
- is_active_on (when the code existed)
- currency_at (currency bounded by lifetime)
- is_eu_member_at / is_eea_member_at / is_eurozone_member_at /
  is_in_customs_union_at (when club memberships applied)

15 queries across 5 surfaces. 130 cross-language cases. 30 gate
checks. No approximations remain.
