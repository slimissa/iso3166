## What this release proves

v1.11.1 retires the last approximation in the registry. `currency_at`
is now lifetime-bounded: it returns None before an entry's `introduced`
date, the current currency after, and None for entries whose
`introduced` is null (source silent).

The "exact" wording was redefined in this release. `currency_at` is
exact about *when a code exists*, but the currency returned is always
the current one (the tree has no historical currency data). This is
documented in QUERIES.md, QUERIES-DECISIONS.md, and the wrapper
docstrings.

## The tri-state (v1.11.0) + lifetime-bounded (v1.11.1) model

is_active_on -> tri-state (True/False/None)
currency_at -> Optional[list[str]] (None = unknown)

Both queries return None when the source is silent. The registry
knows what it knows and says so.

## What's next

v1.12.0 replaces the is_eu/is_eea/is_eurozone heuristics with
exact, date-scoped membership arrays. After v1.12.0, every query
that returns a boolean or a list is exact for dated entries and
None for source-silent entries.
