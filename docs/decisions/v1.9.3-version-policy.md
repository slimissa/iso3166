# v1.9.3 — Version strings in PROVENANCE.md and CONTRIBUTING.md

**Policy: per-minor**

**Status.** Chosen at v1.9.3. A record; the other option is described
below so the choice can be reversed.

## Context

`docs/PROVENANCE.md` ("current as of ...") and `CONTRIBUTING.md` ("As of
...") each state a version. `tools/check_docs_match_tree.py` ties both to
`VERSION` (checks d and e), so a release that forgets to update them fails
the gate. The exact release is already stated, and regenerated on every
release, in `docs/STATE.md`.

## This policy: per-minor

Both files carry `vMAJOR.MINOR` (for example `v1.9`) and the check
compares only major and minor against `VERSION` (or a newer top CHANGELOG
heading). A full `vMAJOR.MINOR.PATCH` string is reported as a mismatch.
Patch releases do not touch the two files; a minor release does.

- Cost: a reader cannot tell which patch release the text was reviewed
  against; `docs/STATE.md` gives the exact version.
- Benefit: no per-patch edits.

## The alternative: per-patch

Both files carry the full version and the check requires an exact match
with `VERSION`. Every release edits both files.

- Cost: two files change on every patch release.
- Benefit: the text always names the release it was last reviewed against.

## Reversing

Change the two strings to the full version, change checks (d) and (e) in
`tools/check_docs_match_tree.py` back to an exact match, and rewrite this
file.
