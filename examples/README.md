# Examples

Each example here is a claim from the registry's documentation turned into a
program you can run. The output is pinned, so if the claim stops being true the
example stops matching and the test suite fails.

```bash
bash examples/run_all.sh            # run every example, print the output
bash examples/run_all.sh --check    # diff each output against its expected_output.txt
bash examples/run_all.sh --write    # regenerate every expected_output.txt
make check                          # the same as --check
```

Standard library only. No example needs a network, a package install or a
compiler. Each one reads the repository's own `iso3166.json`.

## What each example proves

| Example | The claim | Registry data | Other data |
|---------|-----------|---------------|------------|
| [`historical-entity-resolution/`](./historical-entity-resolution/) | A country column that spans decades cannot be validated against today's list. `is_active_on` validates each row on its own date, and its `null` answer must not be read as `false`. | Real: the repository's `iso3166.json`. | Synthetic: 10,000 trades from a fixed seed. |

## Real and synthetic, stated plainly

- **Real** means read from `iso3166.json`: which codes exist, their
  withdrawal dates, their `replaced_by` links, and which `introduced` dates the
  registry holds or leaves `null`.
- **Synthetic** means generated by a script in the example. It is not a sample
  of any real book of trades. Its volumes, weights and the share of
  deliberately wrong rows are chosen by the generator and say nothing about
  real markets.
- An example proves that the **mechanism** works on data with a known answer.
  It does not prove that a real dataset has the same shape, and it does not
  measure how often real systems make these mistakes.

## How an example is laid out

A directory under `examples/` with:

| File | Purpose |
|------|---------|
| `README.md` | The pitch, the failures, the solutions, the output, the honest limits. |
| `analyze.py` | The program. Prints to stdout; exit 0. |
| `expected_output.txt` | The pinned output. `run_all.sh` runs an example only if this file exists. |
| `requirements.txt` | Third-party packages. Empty means standard library only. |

An output must be deterministic: no dates of the run, no paths, no registry
version. The output does depend on the registry's data, so a release that
changes a code, a date or a successor link changes it too; regenerate with
`--write` and read the diff before committing it. That diff is the point.
