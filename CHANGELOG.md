## [1.10.1] — 2026-10-28

The release process tests itself. A tooling release: no registry data, no new
queries, no new fields. Each item answers a specific failure from v1.10.0,
which took six `release.sh` attempts.

### Added

- `tests/test_release_force.sh` — runs `scripts/release.sh --force` in a
  throwaway repository (stub `gh`, stub tools, a 6000-commit history). It
  checks that a plain re-run refuses, that `--force --dry-run` is rejected,
  that `--force` resumes from the post-commit state and tags, and that
  `--force` without a release commit fails cleanly. It also rewrites the
  resume check back to the `git log | grep` pipeline form and requires the
  long-history scenario to fail, so the test is known to catch the SIGPIPE
  bug fixed in v1.10.0 (`63e9d1c`).
- `docs/RELEASE_PATTERN.md` Rule 27, `set -euo pipefail` with
  `if ! cmd | grep` is broken, and its receipt in
  `docs/README-AUDIT-NOTES.md`.

### Changed

- `scripts/release.sh` gate runs `cargo clippy --all-targets -- -D warnings`
  in `wrappers/rust`, as CI already did. v1.10.0's CI failed on an unused
  import that `cargo test` does not report. The README gate list and count
  (28) and `docs/STATE.md` follow.
- **BREAKING for users of the installed `iso3166` script:** the packaged
  command line (`wrappers/python/iso3166/cli.py`) now has the nine derived
  subcommands (`is-eu`, `is-eea`, `is-eurozone`, `region-tree`,
  `borders-transitively`, `succession-path`, `calling-code-for`,
  `currency-at`, `region-countries`) and matches `tools/iso3166_cli.py`. Its
  `successors` and `predecessors` now return the full transitive closure
  (they returned terminal successors and ancestors only), and
  `successors --json` has a `successors` key in place of
  `terminal_successors`. `is-eu`, `is-eea` and `is-eurozone` print
  true/false to stdout and exit 0 whenever the code exists. The packaged
  script calls the `CountryRegistry` methods; it does not import `tools/`,
  which the pip package does not contain. This closes the divergence that
  v1.10.0 recorded under `[Unreleased]`.

### Already in place

- `check_docs_match_tree.py` was already in the `release.sh` gate (after
  `check_state_doc.py`) and in CI; nothing to add.

## [1.10.0] — 2026-10-27

The registry answers questions, not just carries fields. Eleven derived
queries are available in the Python, JavaScript, Rust and Go wrappers and in
`tools/iso3166_cli.py`, all answered from `iso3166.json` at v1.9.3. No new
fields, snapshots or ADRs. The contract is `docs/QUERIES.md`, written from
the tree; its worked examples are re-run against the tree by
`test-derived-queries.sh`.

### BREAKING

- **BREAKING:** the CLI's `successors` and `predecessors` subcommands
  (`tools/iso3166_cli.py`) now return the full transitive closure, matching
  the wrappers. Previously they returned terminal successors/ancestors only.
  This is a breaking change for CLI users; it aligns the CLI with the
  wrappers. `successors YU --raw` now prints `CS`, `ME`, `RS` (was `ME`,
  `RS`); `successors YU --json` has a `successors` key in place of
  `terminal_successors`; `predecessors CS` now prints `YU` (was nothing).
  The fixture's `successors` and `predecessors` sections changed with it
  (`terminal` is now `successors`).

### Changed

- The `is-eu`, `is-eea` and `is-eurozone` subcommands print true/false to
  stdout. Exit codes follow the CLI's standard contract (0 success, 1 not
  found, 2 usage error, 3 registry missing), consistent with every other
  subcommand. This matches the wrappers: the boolean is the answer, the exit
  code is the plumbing. With `--json` they print `{"code": "DE", "is_eu":
  true, "result": "true"}`.

### Added

- `docs/QUERIES.md` — the design contract: signatures in four languages and
  the CLI, semantics, edge cases with the tree's values, a "Worked examples
  index" of 87 reproducible examples, deprecation triggers.
  `docs/QUERIES-DECISIONS.md` — the rationale and the deferred-items table.
- `wrappers/python/iso3166/derived.py` — `DerivedQueries` mixin on
  `CountryRegistry`: `is_eu`, `is_eea`, `is_eurozone`, `region_tree`,
  `borders_transitively`, `succession_path`, `successors`, `predecessors`,
  `calling_code_for`, `currency_at`, `region_countries`.
- `wrappers/javascript/derived.js`, `wrappers/rust/src/lib.rs`,
  `wrappers/go/registry.go` — the same queries with idiomatic names. JS
  results are frozen arrays.
- `tools/iso3166_cli.py` — nine subcommands: `is-eu`, `is-eea`,
  `is-eurozone`, `region-tree`, `borders-transitively`, `succession-path`,
  `calling-code-for`, `currency-at`, `region-countries`.
- `tests/cross_language_consistency.json` — 87 `derived_queries` cases,
  generated by `tools/gen_consistency_fixture.py`.
  `tools/check_cross_language.sh` runs them through all four wrappers and the
  CLI via `tools/cross_language_derived.py`.
- `README.md` — "Derived queries" section.

### Approximate queries

- `is_eu`, `is_eea`, `is_eurozone` use a hardcoded list of the 27 EU members
  at v1.9.3. Deprecated by `is_eu_member_at` in v1.12.0.
- `currency_at` returns an active country's current currency for every date,
  and a withdrawn code's successors' current currency from its withdrawal
  date. It returns `None` where the tree has no currency (every withdrawn
  entry before withdrawal, for example `DD` in 1990). Deprecated by the
  `introduced` field in v1.11.0.

### Known limits

- `calling_code_for` is country level: the tree stores `1`, not area codes,
  and `44` is shared by GB, GG, IM and JE.
- `region_tree("TW")` and `region_countries("Antarctica")` are empty:
  `TW` and `AQ` have no region in the tree.

State documentation. The registry is now externally auditable: a

## [1.8.3] — 2026-10-22

Release correctness. Three defects in `release.sh` and the enrichment
and export tools that made checks pass when they should have failed, or
fail on a correct tree. `iso3166.json`, the schema and the wrapper APIs
are unchanged.

### Fixed

- `scripts/release.sh` — the preflight now refuses unless every CI run
  on HEAD concluded `success`. It names `failure`, `cancelled`,
  `timed_out` and `startup_failure` in its message, and refuses any
  other conclusion too (`skipped`, `neutral`, `action_required`,
  `stale`, none). Before, it matched only `failure`: a `cancelled` run,
  which is what `cancel-in-progress` produces when a newer push
  supersedes it, passed with "CI on HEAD is green", and a `--dry-run`
  ran to the end. Step 4 already refused non-success conclusions, so no
  tag could be created on unverified code; the preflight now stops the
  release before it bumps and pushes the release commit. Found in
  v1.8.2 verification.
- `tools/enrich_field.py --check` — `subregion` accepts `AQ` and `TW` as
  legitimately null (UN M49 assigns them no subregion), and
  `intermediate_region` is required only where M49 defines one, under
  Sub-Saharan Africa and Latin America and the Caribbean. Before, both
  exited 1 on a correct tree (2 and 144 entries flagged). A missing value
  on any entry that does need one is still reported. `--list-missing`
  follows the same rule.
- `tools/export_aggregated.py` — added `--input` and `--output`, and its
  default paths now resolve against the repository root, so it works from
  any directory (v1.8.2 left this tool out because its tests depended on
  the current directory). The tests pass explicit paths into a temporary
  directory instead of changing directory, and check that the committed
  `countries_by_region.parquet` is not touched. Messages for the default
  paths are unchanged.

### Added

- `docs/RELEASE_PATTERN.md` — rule 23: the preflight refuses on any
  non-success CI conclusion.
- `docs/README-AUDIT-NOTES.md` — rule 23 receipt.

### Notes

- This is the last release in the v1.8.x "correctness" phase. v1.9.0
  begins the "state" phase with `docs/STATE.md` and `check_state_doc.py`.
- Hyphenated calling codes (`1-340`) are accepted by `tools/validate.py`
  and `tools/enrich_field.py` since v1.8.2, but `schema.json` still
  requires digits only, so the schema layer would reject one. Deferred
  to a v1.9.x schema ADR.

## [1.8.0] — 2026-10-22

Input contract. The four language wrappers now agree on empty strings,
sentinel numeric codes, and withdrawn-entry behavior. Breaking changes
in all four wrappers; migration notes below and in
`docs/decisions/input-contract.md`.

### BREAKING

- **Python**: `Country.currency_codes`, `calling_codes`, `tlds`,
  `languages`, `borders`, `replaced_by` are now `tuple[str, ...]`
  instead of `list[str]`. Consumers that do `isinstance(x, list)`
  must switch to `isinstance(x, tuple)`. Indexing, iteration, and
  `in` are unchanged. Use `list(x)` where a mutable copy is needed.
- **JavaScript**: `Country` list fields are now deep-frozen. Consumers
  that did `us.currency_codes.push(...)` will throw. Use `.slice()`
  or spread `[...us.currency_codes]` to copy first.
- **Go**: `Active`, `ByAlpha2`, `ByAlpha3`, `ByNumeric` now return
  `Country` (value) instead of `*Country` (pointer). Consumers that
  compare with `== nil` must switch to `country.Alpha2 == ""` or
  check a new `Exists() bool` method. The returned value owns private
  copies of its slices and string pointers, so mutating it can no
  longer corrupt the registry.
- **Rust**: no signature changes; `by_numeric` and `with_numeric` now
  reject `""` and the sentinel `"000"` as documented in the ADR.
- **All wrappers**: `by_numeric("000")` and `by_numeric("0")` now
  return null/nil/None. They previously returned Kosovo (`XK`), whose
  numeric code is the placeholder `"000"`. `by_numeric("")` now
  returns null/nil/None in Python, JavaScript and Rust (it previously
  returned `XK`; Go already returned nil). `search("")` now returns an
  empty list in Python, JavaScript and Rust (it previously returned
  every entry). `region("")` and `subregion("")` now return an empty
  list in Python and JavaScript (they previously returned the entries
  that have no region or sub-region).

### Added

- **DEC-2 ADR** at `docs/decisions/input-contract.md`.
- `with_alpha3`, `with_numeric` (Python/Rust), `withAlpha3`,
  `withNumeric` (JavaScript), `WithAlpha3`, `WithNumeric` (Go) —

  successor consistency; records the source URL in `note`.
- `iso3166 successors CODE` — follow `replaced_by` transitively to
  terminal successors.
- `iso3166 predecessors CODE` — the inverse query, computed from the
  data.
- `iso3166 list --withdrawn-since DATE --withdrawn-before DATE` —
  date filters over the withdrawn set.
- `docs/WITHDRAWN.md` — generated table of every withdrawn code and
  its successor chain.
- `tools/gen_withdrawn_doc.py` — generator with `--check`.

### Changed

- The `withdrawn` array is now complete: 25 entries, one for every
  code ISO 3166-3:2013 lists.
- `tests/cross_language_consistency.json` now carries withdrawn-lookup
  cases. All four wrapper test suites assert agreement on them.

### Fixed

- `tools/validate.py` now rejects a cyclical `replaced_by` graph and
  a `withdrawal_date` in the future.
- `iso3166 successors --raw` and `iso3166 predecessors --raw` accept
  the flag without a field name.

## [1.0.1] — 2026-09-22

Data completion and one behavioral change to the validator.

### Added

- `official_name` populated for all 249 officially-assigned ISO 3166-1
  entries. Sourced per-entry from the ISO 3166-1 Online Browsing
  Platform; each entry's `note` field records the source URL.
- `tools/enrich_official_name.py` — entry tool and completeness check.
  `--check` fails if any officially-assigned entry is missing an
  official name.

### Changed

- `tools/validate.py`: the ISO 4217 snapshot check in the
  cross-reference layer is now blocking. A missing
  `tools/iso4217_snapshot.json` produces a FAIL rather than a WARN.
  A new `--allow-missing-snapshot` flag restores the previous
  behavior for forks and downstream repositories. Recorded in
  decision D5.

### Fixed

- `wrappers/rust/Cargo.lock` records the crate at its actual version.
